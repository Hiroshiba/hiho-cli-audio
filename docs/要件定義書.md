# hiho-cli-audio 要件定義書

## 1. 目的と対象

hiho-cli-audio は、Windows と macOS で動作する Electron 常駐アプリケーションである。グローバルホットキーでOSの既定マイクによる録音を開始または停止し、録音した音声をGeminiで文字起こしする。通常は結果をクリップボードへ保存し、必要な場合はHerdrへ入力する。

対象ユーザーは、設定ファイルを直接編集できる個人利用者一人とする。アプリケーションは通知領域またはメニューバーに常駐し、起動時はすべてのウィンドウを非表示にする。

## 2. 利用の流れ

1. 初回起動時は空のGemini APIキーを含む設定用のYAMLファイルを作成し、設定エラーを表示して終了する。利用者がAPIキーを設定して再起動する。
2. グローバルホットキーを押すと、録音開始時点の出力先を決めて録音を開始する。録音中は小型状態ウィンドウに録音時間を表示し、Herdr対象ならペインIDも表示する。
3. もう一度ホットキーを押すか、自動停止時間に達すると録音を停止する。録音はWebMとして扱い、16kHz、モノラルのWAVへ変換する。
4. WAVをGeminiへ送信して設定した言語の文字起こしを行う。複数の録音がある場合は文字起こしを並行して処理する。
5. クリップボード出力では、文字起こし結果を完了した順にクリップボードへ保存する。Herdr出力では、録音開始時に決めたペインへ入力する。
6. 常駐メニューから履歴を開き、成功した履歴項目をクリックすると本文をクリップボードへ再コピーできる。

## 3. 機能要件

### 常駐と録音

- Windowsでは通知領域、macOSではメニューバーに常駐する。常駐メニューには履歴を開く項目と終了項目を置く。ウィンドウを閉じても常駐を継続する。
- 録音の開始と停止はグローバルホットキーで行う。初期値はWindowsが `Ctrl+Shift+D`、macOSが `Command+Shift+D` とし、YAMLで変更できる。
- 録音にはOSの既定マイクを使う。自動停止時間の初期値は300秒とし、YAMLで変更できる。
- 録音停止後にWebMを16kHz、モノラル、16bit PCMのWAVへ変換し、変換後のWAVを音声ログとして保持する。変換用のWebMは一時データとし、変換後に削除する。

### 文字起こしと出力

- Gemini APIでWAVを文字起こしする。認識言語の初期値は `ja-JP` とし、YAMLで変更できる。初期モデルは `gemini-3.5-transcribe` とする。
- `verbatim` または `smart` の認識モードと、認識時に優先するカスタム語彙をYAMLで指定できる。`verbatim` は発話を維持し、`smart` はフィラー除去と文章整形を行う。カスタム語彙は認識時のヒントとして使い、認識後の機械的な置換は行わない。カスタム語彙は最大1000件とする。
- 前の文字起こしが処理中でも新しい録音を開始できる。文字起こしは並行して処理し、最後に完了した結果がクリップボードの内容になる。
- 通常の出力先はクリップボードとする。成功時は本文を画面に表示せず、状態ウィンドウにコピー完了を3秒表示する。

### Herdr連携

- Herdr連携を正式な出力先として扱う。設定しない場合はクリップボードを使用する。
- macOSでは前面のiTerm2のウィンドウタイトル、Windowsでは前面のWindows Terminalのウィンドウタイトルに `[HERDR]` が含まれる場合をHerdr対象とする。
- 録音開始時に前面状態を判定し、対象なら現在のHerdrペインを取得して送信先を固定する。録音中に前面アプリやペインが変わっても、固定したペインへ送る。録音中の状態ウィンドウには対象のペインIDを表示する。
- Herdr対象の認識結果は改行を空白に変えて固定したペインへ入力し、送信成功時はクリップボードを変更しない。
- 前面状態の判定またはペイン取得に失敗した場合は、その録音の出力先をクリップボードへ切り替える。Herdrへの送信に失敗した場合はクリップボードへ切り替えず、別のペインにも送らない。

### 状態ウィンドウと履歴

- 状態ウィンドウは待機中に非表示とし、録音中、認識中、完了、失敗の状態だけを表示する。録音中は認識中より優先して表示し、認識中は処理中件数を表示する。
- 状態ウィンドウは小型の枠なしウィンドウとし、タイトルバーや最小化ボタンを持たせない。ドラッグで移動でき、位置を保存する。状態や件数が変わっても横幅を変えない。初期位置は画面右上から少し下とする。配色、文字、装飾は `design_reference.html` を参照し、UXや実装方法は参照しない。
- 状態ウィンドウと履歴ウィンドウは、最前面表示を初期値で有効にし、YAMLで変更できる。両ウィンドウの位置を保存する。
- 履歴ウィンドウは起動時に非表示とし、常駐メニューから開く。成功と失敗を合わせて最大10件を新しい順に保持し、上限はYAMLで変更できる。履歴と紐づくWAVは時間経過では削除せず、上限超過時に古い履歴とWAVを削除する。
- 履歴には日時と数行の本文プレビューを表示する。成功項目をクリックすると全文をクリップボードへコピーし、コピーできたことを短時間表示する。失敗項目には日時と「文字起こし失敗」を表示し、クリックしてもコピーしない。
- 履歴ウィンドウが表示中に新しい履歴が作成された場合は一覧へ反映する。

## 4. 設定と保存データ

- 設定はアプリ内画面を設けず、Electronのユーザーデータ保存先にあるYAMLファイルを直接編集する。設定の反映はアプリケーション再起動時とする。
- YAMLでは、最前面表示、ホットキー、自動停止時間、Gemini APIキーとモデル、認識言語とモード、カスタム語彙、履歴件数、状態ウィンドウの初期位置、履歴ウィンドウの狭幅表示、Herdr実行ファイルの設定を指定できる。Herdr設定ではmacOSの実行ファイルパス、またはWindowsのWSLディストリビューション、ユーザー、実行ファイルパスを指定する。
- Gemini APIキーはYAMLファイルに平文で保存する。APIキー未設定とYAMLの構文や値の不正は起動時に検出し、APIキー自体の有効性はGemini呼び出し時に判明する。
- 文字起こしのため、変換したWAV音声をGemini APIへ送信する。Geminiへアップロードした音声は処理後に削除する。
- ユーザーデータ保存先には、設定、ウィンドウ位置、履歴本文と状態、WAV音声ログ、内部ログを保存する。これらのローカルデータは暗号化しない。内部ログは利用者向け画面に表示しない。

## 5. エラー時の動作

- YAMLの構文エラー、必須項目不足、APIキー未設定、数値などの値の不正を起動時に検証する。設定初期化に失敗した場合はエラーを表示して終了する。
- ホットキー登録に失敗した場合はエラーを表示して常駐を続けるが、ホットキーによる録音は利用できない。録音開始に失敗した場合は状態ウィンドウへの表示と内部ログへの記録だけを行い、失敗履歴にはしない。
- WebM受信後の音声変換またはGemini処理に失敗した場合は、状態ウィンドウに簡潔な失敗表示を数秒出して失敗履歴を保存する。個別処理の失敗後もアプリの常駐を継続する。
- 失敗履歴にはエラー詳細を表示せず、詳細は内部ログに記録する。
- Herdrの対象判定またはペイン取得の失敗はクリップボード出力として扱う。Herdrへの送信失敗はクリップボードへ出力せず、別のペインにも送らない。元の認識結果は文字起こし成功を表す成功履歴として保存する。状態ウィンドウにはHerdr送信失敗を表示する。

## 6. 制約と対象外

- 対応OSはWindowsとmacOSに限る。Linuxは対象外とする。
- クラウド同期、ユーザーアカウント、チーム利用は対象外とする。
- 自動貼り付け、アプリ内設定画面、マイクデバイスの選択は提供しない。結果の編集、音声再生、音声ログの保存先を開く機能も提供しない。
- 配布成果物はGitHub Releasesへ公開する。自動更新、署名、公証は対象外とする。
